# 11 — Teaching content and authorship rules

## Instructional purpose
Support the learner's own process: understand the task → explore an idea → select and explain details → draft → revise. These stages can be revisited in any order. The tool is not a lockstep lesson, automatic essay generator or rubric scorer.

Voice: respectful high-school teacher speaking directly to a student. Give a clear starting point, a short concept, one original worked example and a small try-it action. Explain the thinking behind an example; do not provide a pile of unlabeled tips. Avoid elementary-school praise, inflated motivational copy and generic “great work” based on word count.

Personal response does not force private disclosure or only autobiographical experience. Let students use observation, imagination or textual reflection where their assignment permits. The teacher's actual assignment always outranks a generic scaffold.

## Starting content supplied
`content/project-templates.json`: six types with blank scaffold labels/prompts. Practice mode is separate. `content/revision-checks.json`: six review passes with original checklist wording. `content/guides.json`: twelve original short guides with explanations, worked examples and practice prompts. All are original **candidate content for teacher review**, not official Alberta rubrics, approved exam exemplars or a complete English 30 course.

These resources may be previewed immediately. Before classroom release, the English teacher must review language, task-fit and track suitability. Do not block core Blank Project creation because an optional guide is not approved; hide unapproved optional resources through a content publication flag.

## Analysis Explorer preservation
The original source has 9 terms, 5 fixed readings and 90 examples. `legacy-explorer-reference.json` preserves the extracted arrays exactly, labeled review-required. Default new explorer is generic: term → explanation → original micro-example → what the choice does → student try-it. Text-specific packs are optional separately reviewed content, not required source choices for all students.

Scene summaries are labeled scene/paraphrase, not quotations. No invented page numbers, authors, quotations, teacher feedback or numerical rubric weights. Do not use the attributed quotations from concept images as verified literary evidence. Any actual copyrighted or external source content needs its own approved source record and permission/usage review.

## Assignment and rubric handling
Optional prompt and criteria are manually entered or chosen from an owner-authored bundled preset. There is no assumed Brightspace Assignment API integration. Generic criteria are labeled self-checks. Do not present checklist completion as predicted diploma marks or an official Alberta rubric. English 30-1/30-2 selection may filter teacher-approved examples later; it does not prove curriculum alignment by itself.

## Model examples versus student drafts
Every guide example is clearly labeled “Original fictional example”. Copying a guide prompt into a project is allowed through confirmation; auto-inserting model prose into student drafts is not. Evidence insertion copies only the learner's selected source text/notes with a preview. No generated thesis, commentary, conclusion or assessment. AI assistance is absent from MVP.

## Content updates and storage
Guides are packaged application content. State stores bookmarks by stable guide ID, not duplicates of guide prose. Project planner labels/checklists are copied at project creation; old projects keep their familiar wording after a guide release. Adding guides normally does not require a student-data schema change, but still follows package upgrade policy.
