# Additive native response contract

This is an implementation specification for a later separately authorized native pass. No save controls are implemented by the inert teaching fragments.

For each record in PRACTICE_MAP.json, place a visible in-course multiline response directly after the complete supplied stimulus and prompt. Use the distinct proposed record ID unchanged. Add a native C.notes metadata entry with that ID and the task title. Bind the response using the existing data-note-input, data-note-status and data-save-note pattern, with a unique textarea ID, associated label, live status and Save response button. Use the native maximum of 5000 characters and native input/save validation. Do not create a second state owner, a new storage namespace, or an alternative browser-local saving scheme.

The response must be usable in the lesson. Do not substitute a direction to work on paper, an empty stimulus, an inaccessible placeholder or a save button that is only decorative. All proposed tasks are optional, ungraded formative writing; they do not affect the nine required checks, their counts, marks, timers or gating. Keep first attempts and corrections in existing assessment histories unchanged. C.notes does not establish a new immutable first-attempt log for these notes: do not call a saved note a validated independent mastery result.

Learner sequence after implementation: inspect the supplied stimulus, write an explanation, select Save response, receive the native saved/draft status, deliberately open the hint or model as needed, compare against the listed criteria, revise and save again. The model disclosure must use the established intentional reveal pattern. If the approved UI requires saving before model comparison, follow the existing extension model-lock behavior without claiming that all pre-existing optional notes are already locked. Help use is not automatically recorded by the notes contract; therefore do not label these tasks as scored independent checks or infer unaided performance.

Map every new note into the existing All My Work presentation through its C.notes entry. Confirm the complete draft/submitted/reload behavior from the current state owner at integration time; content preparation has not tested it. If the current owner cannot fulfill a needed action without runtime changes, report the exact gap and obtain the required scope decision before implementing it.

Required evidence for each new task: inspect actual stimulus pixels or readable table; type a meaningful synthetic explanation; save; navigate away and back; reload; inspect All My Work and print/export where relevant; open hint/model deliberately; revise and save; verify draft/saved status; verify no required-check completion change. Test one resumed legacy save/import as a separate compatibility gate. Do not call a different existing task's save test evidence for these tasks.

Existing guided selections, whole-set transfer and required checks have their own immutable data and history contracts. Do not route new writing into their IDs, overwrite them, replace their prompts, or claim that model-supported repetition has become unseen assessment evidence.
