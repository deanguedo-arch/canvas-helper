# Visual and document production specification

The accepted direction is the course's existing Biology-style shell and CO1-01 B's teaching hierarchy. Images support a defined reading/decision task. They do not carry the only copy of a required amount or instruction. This pass authors placement, captions and accessible equivalents; it generates no new image assets.

## Shared presentation rules

- A posting must look and read like a posting: fictional organization, role title, relevant duties, supplied requirements, conditions and application instruction. Do not invent a salary, employer logo, address, deadline or credential to make it realistic.
- An experience record begins with who wrote/owns it and why the learner is reading it, then separates situation, action and result. A document title alone does not explain its purpose.
- Pay statements use familiar labelled earnings/deductions/current/YTD groups. Budget and loan tables use aligned money columns and real table headers. Tables are appropriate where comparison is the task; surround them with explicit teaching and interpretation.
- Messages/notices use a named sender/role, date/time where supplied and the exact scenario content. Scam URLs/contacts stay inert; do not make a deceptive mock message clickable.
- Diagram numbers match the editable case text. Captions explain what to notice, not “see image.” Keep colour supplementary to labels.
- Retain existing contextual photography only if it depicts the current case accurately. Caption it as illustration, never evidence of an actual learner/employer. The packet specifies alternatives when a legacy image's labels no longer fit.
- On phones, document groups stack in their reading order. Use an explicitly labelled horizontally scrollable schedule only when preserving row/column comparison is necessary. Do not turn each table cell into an unexplained isolated card.
- A larger document view repeats the same source content, labels and accessible reading order. It must not contain a second unsaved set of response controls.
- The complete written lesson is the primary accessible route. Optional video/audio demonstrates or repeats a named concept; it cannot add facts required for the first time in a quiz.

## Media disposition

The user-supplied replacement videos in CE1-03, CE1-04 and CO2-02 remain candidate optional enhancements. Exact hashes/durations are recorded in meta/media/replacement-media-2026-09-28.json. Earlier .vtt files describe superseded narration and must not be reattached.

Before retaining any video in the new lesson, check the actual narration against the rewritten case, supply synchronized captions and an accurate descriptive transcript, and ensure controls work by keyboard. A written lesson equivalent supplies learning access now but is not claimed to be a verbatim transcript. If the new case and old video conflict, keep the video in the source archive until edited; do not force it into the flow.

Existing FINLIT media can remain in the optional source library. Its presence is not evidence that its content was adapted or reviewed in this authoring pass. No PDF/video viewing requirement or watch timer contributes to lesson completion.

## Visual acceptance at implementation

Inspect one long document, the model and the final controls at desktop and phone widths in each affected batch. Verify no clipped amount, unreadable screenshot text, hidden action, colour-only meaning or inappropriate stock image. Check the actual approved asset bytes are referenced. The learner should be able to point to the supplied fact behind every model claim.
