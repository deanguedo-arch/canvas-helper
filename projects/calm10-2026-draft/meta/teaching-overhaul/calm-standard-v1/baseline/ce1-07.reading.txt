p  :: Learn the basics

h3 ce1-07-foundations-title :: How to revise a plan without losing its purpose

p ce1-07-foundations-purpose :: A change in time or responsibilities can make an old plan stop fitting. Revising means checking what changed and finding a workable next step toward the goal.

h3 ce1-07-foundation-heading-1 :: Separate the goal, route and timing

p ce1-07-foundation-copy-2 :: A goal is what you want to accomplish. A route is how you work toward it. Timing places it into an actual day or week. A new commitment may block a time slot while leaving the goal useful. New evidence may also change the goal itself; identify which part needs revision.

p ce1-07-foundation-copy-3 :: A constraint is a limit the plan must respect. Capacity is the time or resources actually available. A priority is something that needs attention before another task. Do not assume every listed commitment can move.

h3 ce1-07-foundation-heading-4 :: Count a complete block of time

p ce1-07-foundation-copy-5 :: Include preparation, travel, the activity and return or transition time. For a simple example, a 45-minute activity with 15 minutes of travel each way needs 75 minutes. A one-hour free block is too short even though the activity itself is less than an hour.

p ce1-07-foundation-copy-6 :: A buffer is unassigned time that allows for variation. Protect the rest and essential commitments given in the case. Digital reminders can help, while repeated notifications can use the task’s reserved time; choose a habit that supports the plan.

p ce1-07-foundation-copy-7 :: Use old assumption → new evidence → revised route or time → next review. A review trigger names what would require another look, such as a changed timetable.

p ce1-07-foundations-reading :: When you read the case: Read the original plan and the changed weekly schedule together. Before judging a route, check its whole time block against fixed commitments. The first question asks what changed that prevents the old arrangement from fitting.

p  :: Use the method with the case

h3  :: Separate goal, route and timing

p  :: A goal is what you are trying to accomplish. A route is the way you will work toward it. Timing places the route into an actual day or week. Maya's goal is to explore design through two samples. The club and written package are possible routes. Tuesday or Saturday are possible times if they fit the records.

p  :: A changed constraint does not automatically cancel the goal. It does require checking the route. Conversely, new experience might show that the goal itself no longer fits. The useful question is which part the new evidence changes, rather than treating every revision as failure.

h3  :: Count the whole block

p  :: An hour-long session can require two hours when travel is included. Do not overlap travel with the task that requires being somewhere else. A plan must also allow transitions: putting materials away, getting ready for the next commitment or dealing with a small delay. A buffer is time left unassigned so every step does not depend on a perfect sequence.

p  :: Use the time line:

p  :: Travel or preparation → focused activity → return or transition → next commitment.

p  :: If any part overlaps a fixed commitment, the route needs a change. Having a total number of “free hours” is not enough if those hours occur at the wrong time or in fragments too short for the task.

h3  :: Make digital habits serve the plan

p  :: Digital tools can support planning through calendars, reminders, saved notes and accessible materials. They can also consume the time reserved for the task. In a one-hour block, repeated message checking can leave less time for the example and draft even though the calendar still says “one hour.” A useful plan names one manageable habit: silence nonessential notifications during the example, keep the task document visible or put a reminder at the transition time.

p  :: The habit is a support, not a claim that everyone can solve every barrier through willpower. If the required task still cannot fit, revise the route or amount of work. Keep privacy in mind when using a digital planner: fictional labels are enough for this course, and a public calendar need not reveal another person's personal circumstances.

h3  :: Treat overload as information

p  :: Time pressure can make a plan stressful. A reasonable planning response is to reduce conflicting demands, break a task into workable pieces or use an available support. Removing sleep, meals or all recovery to make the chart balance would hide a new problem. In this case the protected rest period stays protected.

p  :: Support does not have to mean someone making the decision for you. Here the alternative written package and clear scheduling notice provide support. A precise future question can identify an uncertainty; no actual message needs to be sent to finish the lesson.

h3  :: State when the plan will be reviewed

p  :: A revision note should record old assumption → new evidence → changed route/timing → review trigger. A review trigger is the event that makes another look useful: a changed timetable, unavailable materials or evidence that the task takes longer than planned. Include a date too, so “review later” becomes an action you can locate.
