# CALM visual learning audit

The approved CALM course would benefit most from visuals that explain timing, money movement, document structure and relationships. Several lessons already have effective spatial or procedural diagrams. Add a visual where it helps a student understand something that is difficult to see in prose; a photograph in every lesson would add little instructional value.

This is a proposal for the existing 40 lessons. The course has not been edited. Placements below refer to the canonical preview at [the course index](http://127.0.0.1:4195/). All numerical examples belong to the supplied teaching cases, not current offers, forecasts or legal advice.

## Start with five different teaching needs

Build these five first so we can review the visual language across the course before producing the remaining diagrams:

1. **Read a pay stub:** annotate the document and connect gross pay, deductions and net pay.
2. **Build a flexible budget:** show the account balance changing on actual payment dates, including when it goes below zero.
3. **Read a loan payment schedule:** divide one payment into interest and principal, then carry the remaining balance into the next month.
4. **Separate an account from what it holds:** distinguish the account arrangement from the savings or investment inside it.
5. **Build a high-school route:** show course prerequisites, portfolio deadlines and reserved core-course blocks on a timeline.

These cover document reading, graphs, calculations, conceptual relationships and planning. They also give us reusable presentation patterns without making every visual look identical.

## How the visuals should teach

- Introduce each visual with a sentence explaining what the student is looking at and why. Follow it with an explanation of the important relationship. An unexplained diagram can create the same confusion as an unexplained text block.
- Place essential visuals beside the explanation they support, before the question requiring that understanding. Keep them visible. A larger view or optional step demonstration can open on demand.
- Use the worked teaching case for completed calculations. Guided-practice answers remain behind their existing intentional model reveals; independent-task answers must not appear in advance.
- Keep the existing document, prose, tables, professional videos and transcripts available. A visual complements these forms rather than replacing the only complete explanation.
- Use the established course typography, colours and spacing. Label parts directly; never make colour alone carry meaning. Avoid tiny lettering, decorative backgrounds and unfamiliar unexplained codes.
- Prefer editable SVG or HTML for diagrams containing words, amounts, dates and formulas. Use raster illustration only when recognizing objects, actions or a physical space is the teaching purpose.
- Provide a useful text equivalent. For a graph, retain the underlying accessible table and explain its conclusion. On mobile, reflow or offer a larger view without shrinking important labels beyond readability.
- Keep unknown quantities visibly unknown. Do not draw them as zero, promise outcomes, or turn conditional evidence into certainty. Validate scales, units, rounding and arrows against the manuscript before insertion.
- Add no required activity, response field or completion condition simply to justify an image. An optional visual control must preserve existing saved-work contracts.

## Review every lesson

**First** means high instructional value. **Next** means a useful addition after the first patterns are approved. **Optional** means existing prose, documents or media may already do the job; use a small annotation rather than another large image. **Keep** means an existing approved visual already addresses the need.

## Implementation and review boundary

This sweep proposes placements and content; it adds no course images, interactions or response fields. Start with the five examples above, review them in the actual course shell, then use the approved visual treatments for the remaining priorities. Preserve the current professional media, approved images, stable task IDs, history, completion controls and canonical storage.

For each implemented visual, check its teaching claim against the supplied record, exact manuscript/graphic values, text equivalent, desktop/mobile readability and location before its dependent question. Inspect interactive or keyboard behaviour only when controls are added. Broader course, Studio, SCORM and release checks remain part of a separately authorized rollout.

Source provenance, complete lesson coverage, media counts and suggested anchor verification are recorded in `inventory.json` beside this report. A future manuscript change should prompt a fresh check of the affected visual brief.
