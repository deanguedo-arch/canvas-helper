# Science 24 Games — Unified Visual Standard v0.1

**Status:** Approved visual direction for the Science 24 Games project  
**Approved reference:** `Science24_Games_Visual_Reference_A1_v0.1.png`  
**Purpose:** Keep all Science 24 games visually consistent with the existing Next Step / Science 24 course family.

## 1. Canonical aesthetic

Use the approved **Next Step Science Course** visual language, not a separate arcade/game skin.

The experience should feel like a polished interactive extension of the existing Science 24 course: modern, academic, science-forward, highly readable, restrained, practical, and premium without becoming futuristic or childish.

### Core visual character
- Clean educational UI rather than a traditional video-game HUD.
- Strong hierarchy, generous spacing, and simple three-zone layouts where appropriate.
- Flat-to-lightly-dimensional surfaces; subtle shadows only.
- Scientific photographs/illustrations may provide context, but exact scientific content stays in authored UI, labels, diagrams, tables, graphs, equations, and controls.
- The interface should look at home beside existing Next Step Science 24 lessons.

## 2. Color school

The real Science 24 course screens are the source of truth.

### Primary palette
- **Near-black / charcoal:** global header, navigation, strong anchors.
- **Deep forest green:** panel headers, primary accents, active states.
- **Brighter course green:** progress, selected states, confirmations, buttons used sparingly.
- **White:** dominant content surface.
- **Very light gray / warm off-white:** page background and secondary surfaces.
- **Pale green-gray:** subtle fills, selected cards, info areas.

### Supporting rules
- Teal/cyan is not the dominant brand color for this game suite.
- Avoid neon blue, sci-fi cyan glow, saturated gamer gradients, or glassmorphism as the main language.
- Green communicates course identity and active/selected states, but should not flood the whole screen.
- Black/charcoal + green + white should remain the recognizable base across every game.

## 3. Typography

- Clean, modern sans-serif family consistent with the course shell.
- Large, bold lesson/game titles.
- Strong medium-weight panel titles.
- Sentence-case body copy for readability.
- Small uppercase may be used sparingly for labels, stages, and metadata.
- Avoid novelty fonts.
- Handwritten annotation styling may appear only as a small supporting accent, never for core instructions or scientific content.

## 4. Shared game shell

All games should inherit a recognizable shell.

### Header
- Dark charcoal / near-black course-style header.
- `Science 24` identity on the left.
- `Next Step` identity on the right.
- Optional short course-style tagline or progress metadata.

### Main workspace
Prefer a clear, bounded layout such as:
1. **Context / Case / Mission**
2. **Evidence / Model / Manipulation area**
3. **Reasoning / Claim / Decision area**

Not every game must literally use three columns, but the same hierarchy should be recognizable.

### Bottom strip
A restrained feedback / key-idea / progression strip may be used across the suite.

## 5. Component language

- White cards with thin neutral or pale green-gray borders.
- Dark forest-green section headers.
- Rounded corners: modest, not bubbly.
- Minimal shadows.
- Buttons are practical course controls, not arcade buttons.
- Selected answer/evidence states: pale green surface + green border/accent.
- Correct state: green plus icon/text cue.
- Warning/revise states should use label + icon, not color alone.
- Keep controls large enough for touch and readable at narrow widths.

## 6. Scientific visuals

### Context visuals may use
- Lab/workshop photography or polished generated illustration.
- Objects such as glassware, equipment, vehicles, devices, energy systems, or fictional environments.
- Shallow-depth photography when it improves realism and focus.

### Exact science must remain deterministic UI
Do not bake critical science into generated imagery. Keep these as authored interface elements:
- equations
- atom counts
- reaction labels
- graph axes and values
- energy quantities
- force/momentum calculations
- pedigree relationships
- allele labels
- route logic
- measurements
- answer-critical text

## 7. Decorative science language

Use sparingly:
- flask / molecule / graph / magnifier / energy icons
- thin line diagrams
- small molecular or grid motifs
- subtle course-style scientific marks

Avoid:
- glowing sci-fi grids
- excessive HUD markings
- fake holograms
- cartoon mascots
- dense decorative chemistry wallpaper
- game-like score clutter that competes with the learning task

## 8. Tone

The visual system should communicate:
- serious enough for exam preparation
- approachable enough for independent learners
- clearer than a textbook
- visually better than a worksheet
- consistent with Next Step Continuing Education
- science is something the learner *does*, not just reads

## 9. Canonical A1 reference

The approved A1 Reaction Detective mockup establishes the current baseline:
- course-style black/charcoal header
- Science 24 + Next Step branding
- black/forest-green/white palette
- large clean title
- three major content zones: **The Case / The Evidence / Your Reasoning**
- photographic scientific context
- authored evidence cards and values
- green selected state
- restrained bottom **Feedback / Key idea** strip
- minimal decoration

Future games should feel like siblings of this screen, not separate visual brands.

## 10. Hard consistency rule

**Do not redesign the visual identity game-by-game.**  
Mechanics and scientific representations may change, but the course shell, palette, typography, spacing philosophy, component language, feedback treatment, and overall level of visual restraint stay consistent unless Dean explicitly approves a new visual-system version.
